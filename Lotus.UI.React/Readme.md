Модуль компонентов Lotus.UI.React для Frontend приложений платформы Lotus

Библиотека UI-компонентов платформы Lotus. На ней собираются экраны приложений: формы, справочники, CRUD-таблицы, панели и визуальный каркас поверх Mantine 9 и React 19.

Связка с доменной моделью идёт через `lotus-core`: `ObjectInfo`, валидаторы, локализация, команды, изображения, типы запросов/ответов. Стили строятся на собственной дизайн-системе (размеры, цвета, CSS-переменные) и Emotion, а не только на токенах Mantine.

Импорт точечный: `lotus-ui-react/components/DataView`, `lotus-ui-react/hooks`, `lotus-ui-react/provider` и так далее. Каталог компонентов смотрите в Storybook: `npm run sb` (порт 6006).

Пакет: `lotus-ui-react` · версия `4.0.0`


## Дизайн-система и инфраструктура

### `designSystem`

Единый набор визуальных настроек: цвета, шрифты, фон, рамки, текст, шкалы размеров (шрифт, отступы, радиусы, иконки, gap). Класс `DesignSystem` собирает параметры, применяет светлую/тёмную схему и выкладывает значения в CSS-переменные. `DesignSystemHelper` и константы нужны, чтобы компоненты брали одни и те же токены, а не хардкодили пиксели.

### `provider`

Обёртки приложения. `DesignSystemProvider` создаёт дизайн-систему, пишет её в контекст и может сохранять схему в storage. `LocalizationProvider` держит язык (`ru-RU` и другие типы из `lotus-core`), синхронизирует `document.lang` и перерисовывает дерево при смене локали. Без этих провайдеров токены и подписи компонентов живут каждый сам по себе.

### `base`

Общие prop-контракты элементов: фон, рамка, контейнер, отступы, текст, иконка. Хелперы (`BackgroundPropertiesHelper`, `ContainerPropertiesHelper` и остальные) превращают эти props в CSS, чтобы Box, Button и поля ввода говорили на одном языке. Это не визуальные компоненты, а слой соглашений для всей библиотеки.

### `types`

Литеральные типы UI: размеры (`xxs`…`xxl`), ориентация, тени, акценты фона и шрифта, placement иконки, CSS-алиасы ширины/gap/выравнивания. `IContextRenderBase` передаётся в кастомный рендер пунктов селектов и карточек. Типы связывают дизайн-систему с props компонентов.

### `helpers`

`CssPropertiesHelper` склеивает объекты стилей и отфильтровывает пустые значения перед `@emotion/css`. Нужен там, где компонент собирает стиль из нескольких хелперов `base` и не должен писать в DOM `undefined`.

### `interactivity`

Логика hover/focus/disabled/selected для «своих» контролов (в первую очередь кнопка). `InteractivityLogic` выбирает CSS по модели (`filled` и другие) и состоянию; отдельно считаются фон, рамка и текст. Ripple и hover-эффекты подключаются хуками, чтобы интерактив не дублировался в каждом компоненте.

### `hooks`

Набор React-хуков без привязки к конкретному экрану. `useForm` собирает значения native-формы в объект. `useInstanceProxy` / `useInstanceProxyAsync` / `useProxyObject` подписывают UI на `RefreshProxy` из `lotus-core` и чистят `destroy`. `useMediaQuery`, `useScreenResizeOrOrientation`, `useResizer`, `useMutationObserver` следят за вёрсткой; `useInterval` и `useRippleEffect` — за таймерами и материалом кнопки.

## Компоненты

### Common

#### `ContainerControl`

Общая оболочка поля: подпись, описание, ошибка, `required`, inline-раскладка label+control. На ней сидят Inputs, Selects, Slider и Switch, чтобы формы выглядели одинаково. Сам по себе контрол не редактирует данные — только раскладывает слоты.

#### `Primitive`

Мемоизированные куски: `Icon`, `Image`, `Item`, `Option`, `Span`. Иконка рендерит react-icons / ресурсы `imageDatabase` с размерами дизайн-системы; Image умеет CORS и растр из ядра. Item/Option — типовые ячейки списков и комбобоксов, чтобы селекты не копировали разметку пункта.

### Layout

#### `Box`

Базовый `div` с фоном, рамкой, margin/padding и опцией центрирования контента (горизонтально, вертикально, по центру). Точка сборки простых блоков, когда панель или грид ещё не нужны.

#### `Panel`

Box с заголовком (строка или `Label`), который можно сместить и оформить отдельно. Удобен для карточек настроек и группировки полей. Размер панели стыкуется со шкалой `TSizeType`.

#### `Grid`

CSS Grid с шаблоном колонок/строк, gap из дизайн-системы и выравниванием по осям. Используется для карточек, `BlockValues` и любых регулярных сеток без привязки к Mantine Grid.

#### `HorizontalStack` / `VerticalStack`

Flex-ряды и колонки: spacing, выравнивание, wrap, фон и рамка из тех же general-props. Это основной способ собрать тулбар, форму в одну линию или столбец действий.

### Display

#### `Text`

Текст с типографикой дизайн-системы: цвет, вес, выравнивание, disabled. Может быть строчным или блочным; `asBadge` рисует цветной бейдж. Базовая надпись без иконки.

#### `Label`

`Text` плюс иконка слева/справа/сверху/снизу с gap. Заголовки панелей, пунктов меню и подписи, где нужен глиф рядом со словами.

#### `Divider`

Горизонтальный или вертикальный разделитель с толщиной, стилем и цветом линии. Флаги `nm*` снимают внешние отступы с нужной стороны, чтобы линия стыковалась с соседними блоками.

#### `BlockValue`

Пара «название — значение» с акцентной полосой (цвет токена или CSS). Нужен для карточек объекта и сводок, когда таблица избыточна. Подписи и значения настраиваются отдельно через `Label`.

#### `BlockValues`

Сетка из нескольких `BlockValue`: задаются число строк/столбцов и ориентация заполнения. Один проход props разворачивает карточку свойств сущности.

### Inputs

Поля на Mantine Input, обёрнутые в `ContainerControl`. Общий контракт: `value`, `onChange` события Mantine и упрощённый `onChangeValue` с уже извлечённым значением, плюс `disabled` и стандартные label/error.

#### `TextInput`

Однострочный текст. Для имён, поиска и любых строковых свойств objectInfo.

#### `TextAreaInput`

Многострочный ввод той же схемы props. Для описаний и длинных комментариев.

#### `PasswordInput`

Пароль с маскированием Mantine. Та же контейнерная обвязка, чтобы форма логина не выбивалась из остальных полей.

#### `NumberInput`

Число с min/max/step. `onChangeValue` отдаёт `number`, без разбора события.

### Controls

#### `Button`

Собственная кнопка (не Mantine Button): варианты отображения, иконка, selected, hover/focus через `interactivity`, опциональный ripple. Для тулбаров и игровых/кастомных поверхностей, где нужен полный контроль CSS.

#### `Switch`

Переключатель boolean на Mantine Switch внутри `ContainerControl`. Есть и событие Mantine, и `onChangeValue(checked)`.

#### `Slider`

Ползунок числа с min/max/step и подписью. Используется и в формах, и в `ImageEditor` (масштаб).

### Selects

Селекты работают с массивом произвольных `TItem`, а не только со строками: `getValueItem` / `getLabelItem` / `getDisabledItem`, `imageDatabase`, кастомный `renderItem` / `renderValue`. Это мост к справочникам Lotus.

#### `Select`

Одиночный выбор. Под капотом `SelectEx`, пункты могут быть иконка+текст. Значение наружу — исходный объект, не id-строка.

#### `MultiSelect`

Множественный выбор с pill; кастомный рендер выбранных через `MultiSelectEx`. `onChangedItems` отдаёт массив исходных элементов.

#### `Segmented`

Сегментированный контроль для коротких enum-списков. `useAccentSelection` подкрашивает активный сегмент акцентом дизайн-системы.

#### `GallerySelect`

Выпадающая галерея: сетка превью, поиск, пагинация, ресайз области. Для выбора сущности «картинкой», а не строкой.

#### `ImageGallery`

`GallerySelect` над `IImageDatabase`: список всех картинок ресурса, выбранное изображение и фиксированный размер превью.

### Extended

#### `SelectEx`

Расширенный Mantine Select: `renderValue` для поля в закрытом состоянии (не только option в списке). Нужен TableView и Lotus-селектам, когда выбранное значение — карточка или иконка.

#### `MultiSelectEx`

То же для MultiSelect: `renderPill` вместо стандартной таблетки. Совместим с Mantine 9 factory API.

### DataView

#### `TableView`

CRUD-таблица по `IObjectInfo`: колонки, фильтры, сортировка, пагинация и редактирование собираются из дескрипторов свойств. Данные грузятся серверно (`manualPagination` / `manualFiltering` / `manualSorting`) через `onGetItems` и типы `IRequest`/`IResponsePage`. Есть создание, правка (строка или модалка), удаление, валидация, выбор строк, карточный вид и пресеты вроде `TableViewPropsPreset.getCrud()`.

#### `CardView`

Сетка карточек тех же сущностей: выбор элемента, фильтры/сортировка objectInfo, пагинация MRT. `renderCard` задаёт внешний вид; удобно как альтернатива таблице на том же API.

### Editors

#### `ImageEditor`

Редактор превью на canvas: загрузка файла/URL, масштаб, позиция, круглый кроп, CORS. По сохранению отдаёт `Blob` в `onSavePreview`. Ориентация вертикальная или горизонтальная, вписывается в стеки Layout.

## Модули предметной области UI

### `modules/commands`

`CommandElement` рисует `BaseActionCommand` из `lotus-core` как иконку, кнопку, пункт меню или NavLink. Учитывает доступность команды, иконку из `imageDatabase` и навигацию react-router. Один объект команды можно показать в тулбаре и в меню без дублирования логики.

### `modules/feedback`

Тосты на `@mantine/notifications`. `Notifications.showResult` понимает `IResult` ядра: успех, ошибка, список замечаний. Типы алерта/feedback в `domain` задают семантику сообщения, UI только отображает.

## Внешние пакеты внутри репозитория

### `external/mantine-react-table`

Вендорный Mantine React Table под текущие Mantine 9 и TanStack Table v9. Это движок `TableView`/`CardView`: колонки, фильтры, пагинация, тулбар, закрепление колонок. Публичный вход — `lotus-ui-react/external/mantine-react-table`, если нужна «голая» таблица без objectInfo.

## Игровые компоненты

`gameComponents` (MetalButton, BlackButton) — стилизованные кнопки для игровых/декоративных экранов. В package exports не входят, живут в Storybook. Не путать с основным `Controls/Button`.
